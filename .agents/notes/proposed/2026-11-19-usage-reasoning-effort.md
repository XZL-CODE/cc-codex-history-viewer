# Agent Note: 用量明细显示推理档位

Status: proposed

## Problem

推理档位（effort）决定一次调用会输出多少思考与回复 Token，同一会话里可能中途切换。
对话详情的 Token 用量明细看不出某次调用、某段输出是在哪个档位下产生的。需要决定档位
从哪读、在哪显示、没有记录时怎么办，以及是否进入索引。

## Proposal

- 只在对话详情显示，概览统计不加档位维度。理由：用户确认的范围。
- 四处显示：每条助手消息用量标签的悬停、调用图的悬停、输出指标卡第二行的会话汇总
  （单一档位只写档位，多档位列出各档位调用次数，含子代理）、按模型表同一模型按档位
  分行。理由：用户确认四处都要，按模型表分行便于对比同一模型不同档位的输出与成本。
- 显示记录里的原值（`low` / `medium` / `high` / `xhigh` / `max`，Codex 还有
  `minimal`），不翻译、不映射。理由：两个产品的界面叫法不同（Claude 应用把 `xhigh`
  叫 Extra），原值没有歧义。
- 记录里没有档位时显示「未记录」，不推测默认值；整个会话都没有档位时汇总行不出现。
  理由：默认档位随 CLI 版本、模型与设置变化，推出来的值不可靠。
- Claude Code 读助手记录顶层的 `perTurnEffort`，缺失时退回 `effort`；Codex 读每轮
  `turn_context.effort`，同一轮的调用共用，下一轮没有该字段时不继承上一轮。理由：
  `perTurnEffort` 推测是本轮实际档位，`effort` 是会话设置；Codex 每轮重新声明上下文。
- 档位只作展示维度，不参与成本估算。理由：档位不改变单价。
- 索引的每条调用记录档位，缓存 schema 升到 v7，升级后首次启动全量重建一次。理由：
  调用图与汇总的调用来自索引，子代理调用不在本会话文件里，只能从索引拿到档位。

## 与已有决定的关系

[对话详情的 Token 用量明细](../implemented/2026-09-28-conversation-usage-breakdown.md)
的 Proposal 写明「按模型表只在多模型会话出现」。按档位分行后，单模型但用了多个档位的会话
也会出现这张表（行数大于 1 即显示），与该条字面不符，待用户裁定。

## Risks

- `effort` 与 `perTurnEffort` 何时取值不同尚未见到实例：从菜单切换档位时两者同时变化。
- Codex `turn_context.effort` 的位置依据对 rollout 格式的了解与合成 fixture，尚未用真实
  rollout 核对。

## Verification

合成 fixture 锁定：Claude 优先 `perTurnEffort`、退回 `effort`、形状不符只丢档位不丢整行，
详情与索引取值一致；Codex 档位随 `turn_context` 逐轮更新且不跨轮继承；按模型表按
（模型，档位）分行，模型按总量排序、同一模型的行按档位从低到高相邻，行之和等于调用之和。
Claude Code 2.1.328 的真实记录中确认了两个字段的位置与切换档位后的取值。

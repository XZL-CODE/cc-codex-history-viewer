# Agent Note: 自动检查更新的时机

Status: proposed

## Problem

自动检查只在启动后进行，每天最多一次（手动检查也算在内），失败后本次运行不再重试。应用一直开着，或当天已经查过时，
新发布的版本要等隔天重启才会提示，发版后只能到设置里手动检查。

## Proposal

- 启动 5 秒后、窗口重新获得焦点或重新显示时、运行期间定时，都判断是否到期，距上次检查满一小时才发请求。理由：用户
  确认间隔一小时；一直开着的应用和切回应用时都能在一小时内看到新版本；请求的只是 Release 上的版本清单。
- 检查失败也记为一次检查，一小时后再试，仍不弹提示。理由：启动时网络或代理还没就绪，不应让本次运行再也不查，也不应
  失败后反复请求。
- 上次发现的新版本还没装时，启动后不等满一小时就查。理由：沿用原有行为，重启后顶栏提示仍在。
- 提示方式、手动检查、自动检查开关、请求的文件与隐私说明不变。理由：用户只要求改检查时机。

## 与已有决定的关系

[应用内检查更新与一键更新](../implemented/2026-10-11-in-app-updates.md) 的 Proposal 写明「启动后自动检查，每天最多
一次」。用户裁定改为本 Note 的检查时机；本 Note 进 `implemented/` 时，该条改标已取代。

## Verification

前端没有单元测试框架；在浏览器中用模拟 IPC 和假时钟核对：启动延迟内的焦点不触发检查，启动 5 秒后检查，一小时内的
焦点不查，满一小时由定时或焦点触发，失败记为一次检查并保留待装版本，有待装版本时启动后立即检查，关闭开关后都不查。
窗口焦点事件在 macOS 与 Windows 的 WebView 里是否触发尚未在真机上核对；不触发时由每 5 分钟一次的到期判断兜底。

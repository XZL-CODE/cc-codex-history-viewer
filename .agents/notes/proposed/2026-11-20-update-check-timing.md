# Agent Note: 自动检查更新的时机

Status: proposed

## Problem

自动检查只在启动后进行，每天最多一次（手动检查也算在内），失败后本次运行不再重试。应用一直开着，或当天已经查过时，
新发布的版本要等隔天重启才会提示，发版后只能到设置里手动检查。

## Proposal

- 每个整点检查一次；启动 5 秒后、窗口重新获得焦点或重新显示时，本小时还没查过也查一次。理由：用户改为按整点检查，
  发版后最迟到下一个整点就能看到，时间可预期，不取决于上次检查的时间；请求的只是 Release 上的版本清单。
- 检查失败也算本小时查过，下个整点再试，仍不弹提示。理由：启动时网络或代理还没就绪，不应让本次运行再也不查，也不应
  失败后反复请求。
- 上次发现的新版本还没装时，启动后不等满一小时就查。理由：沿用原有行为，重启后顶栏提示仍在。
- 提示方式、手动检查、自动检查开关、请求的文件与隐私说明不变。理由：用户只要求改检查时机。

## 与已有决定的关系

[应用内检查更新与一键更新](../implemented/2026-10-11-in-app-updates.md) 的 Proposal 写明「启动后自动检查，每天最多
一次」。用户裁定改为本 Note 的检查时机；本 Note 进 `implemented/` 时，该条改标已取代。

## Verification

前端没有单元测试框架；在浏览器中用模拟 IPC 和假时钟（Asia/Shanghai 时区）核对：首次启动 5 秒后检查，同一小时内的
焦点不查，之后每个整点各查一次；本小时已查过时启动不查，上个小时查过时启动就查；有待装版本时启动必查；失败算本小时
查过，下个整点重试并保留待装版本；睡眠跨过整点后，切回窗口立即补查，不切窗口时由每 5 分钟的兜底补查；关闭开关后都不查。
整点定时器多等 1 秒触发，避免定时器略早时还算在上个小时。窗口焦点事件在 macOS 与 Windows 的 WebView 里是否触发
尚未在真机上核对。

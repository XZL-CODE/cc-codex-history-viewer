# Agent Note: 对话 Markdown 的渲染规则

Status: implemented

## Problem

对话详情里多处 Markdown 以原文显示或显示不对：中文标点旁的粗体失效、思考预览带「**标题**」、Codex 的
建议追问指令原样显示、子代理报告与计划一律等宽原文、标题与大纲预览是带标记的原文、段内单个换行被合并。
需要决定哪些内容按 Markdown 渲染、哪些保持原文，以及预览与标题怎么显示。

## Proposal

- 子代理报告与计划按 Markdown 渲染：Task / Agent 的指令与结果、ExitPlanMode 的计划跟随「Markdown / 原文」
  开关；命令输出、文件内容等其他工具结果保持原文。理由：它们是模型写的 Markdown，与助手回复同类；其他工具
  结果是程序输出，空白与缩进有意义。
- 标题与大纲预览用纯文本摘要：会话列表标题、大纲轮次预览、外部会话标题去掉 Markdown 标记，跳过 Codex 注入
  的上下文包装取真正的提问；消息正文、复制与搜索仍用原文。理由：一两行的预览里标记只是噪音，包装会让标题
  千篇一律。
- 段内单个换行按换行显示。理由：与 GitHub 评论和「原文」模式一致，中文行之间不再多出空格。
- 用户消息保持原文。理由：随手输入的 * _ # 与路径会被误当成格式，并与首页、搜索、Prompt 列表的原文展示一致。

## Decision

已按 Proposal 落实。同时修正的渲染缺陷：

- 中文标点旁的粗体、斜体与删除线：remark-cjk-friendly 与其删除线插件。
- Codex 文本指令（`:codex-followup[…]{prompt=…}`、`:codex-file-citation{path=…}`）在解析前改写成私有协议
  链接，显示为「↪ 标签」，悬停看完整提问或路径；围栏与行内代码里的不动。
- 裸网址遇到中文标点即结束（只处理自动链接）；`<br>` 换成换行、单个 HTML 注释去掉，其余原始 HTML 仍按文本显示。
- 指向本地路径的链接不可点击，悬停显示解码后的目标：外部会话里的路径属于别人的电脑，本机会话也不替用户打开文件。
- 摘要只去掉成对且贴着文字的 `**` / `~~` 与链接标记，行内代码原样保留，`__` 不当作标记。
- Codex 代码模式的工具输出（`input_text` 内容数组）直接显示文本。
- 导出的工具结果标题写成「↩ 工具结果 · 工具名」，外部会话据此还原；旧文件按调用顺序推断（见开发文档 §12.1）。

新增依赖：remark-cjk-friendly、remark-cjk-friendly-gfm-strikethrough（2.3.1）、remark-breaks（4.0.0）。

## Consequences

- 手动折行的 Markdown 段落按原样断行。
- 原始 HTML 除 `<br>` 与注释外仍显示为文本（不解析、不执行）。
- 旧版导出的工具结果名是推断的，个别调用缺结果时可能对不上。

# Agent Note: 更新弹窗列出跳过的版本，说明跟随界面语言

Status: implemented

## Problem

更新弹窗只显示最新一版的 Release 正文。用户落后好几个版本时（如装着 v0.15 而最新是 v0.18），中间几版改了什么
看不到。Release 正文是中英双语，弹窗把两种语言都显示出来，篇幅翻倍。

## Proposal

- 弹窗从新到旧列出用户跳过的版本，最多 3 个，每版一个小标题（版本号与发布日期）；落后更多时，底部一行说明只列出
  最近 3 个，并可在浏览器打开全部版本的 Release 列表。理由：用户把 3 或 5 交给 Agent 决定；每版说明每种语言有
  三四条长句，3 个版本已超过弹窗一屏，5 个要翻很久。
- 各版说明在发版时写进 `latest.json` 的 `history`：本版加之前最近 4 个已发布的正式版，取自各版 Release 正文，
  去掉安装说明。应用按自己的版本号挑出比它新的版本。理由：应用本来就读这个文件，不新增请求和联网地址，「只请求
  本仓库 GitHub Release 上的文件」的隐私说明不变；多带的版本用来判断还有没有更早的没列出。
- 说明只显示界面语言（设置里选的中文或英文，首次跟随系统语言）那部分，切换语言立即生效。Release 正文没有逐条标注
  语言，按每条里汉字与英文单词的比例判断；判断不出另一种语言时整段显示。理由：用户要求按客户端语言显示；沿用
  现有正文格式，以往各版也能拆开，不用改写已发布的 Release。

## Decision

已按 Proposal 落实，随 v0.16.0 发布。从 v0.16.0 起的更新说明不再写「装着 v0.13.0 及之后版本的应用…」那句，
避免列出多个版本时重复。

## Alternatives considered

- 应用直接请求 GitHub API 的 Release 列表：要新增 `api.github.com`，未登录每小时 60 次的限额，隐私说明也要改。
- 每版说明改成逐条标注语言的结构化格式：已发布的 Release 没有标注，仍要按文字判断，收益不大。

## Consequences

- 只对装着带此功能版本的应用生效：v0.15.1 及更早的应用更新到下一版时，仍只看到最新一版的双语说明；从再下一版起，
  落后的用户才能看到版本列表和单语说明。
- `latest.json` 的 `history` 只有发版工作流的 `publish` 任务会写；该步骤失败时 Release 停在草稿，重跑即可。
- 按文字判断语言依赖写法：每条说明只用一种语言，英文条目不大段引用中文。写法要求见发布指南 §2。

## Verification

- Rust 单元测试（`updater::tests`）：只取介于当前版与最新版之间的版本、新的在前、去重，最新版用清单正文；清单没有
  `history`、格式不对或版本号解析不了时只返回最新版。
- 前端没有单元测试框架；用 Node 对 v0.15.0、v0.13.1、v0.12.0 的真实 Release 正文核对中英拆分（条数一致、无混入、
  列表保持紧凑），并核对双语小标题、段落、嵌套列表、代码块与只有一种语言的情形。
- 在浏览器中用模拟 IPC 打开弹窗，核对落后 4 个版本（列 3 个并提示）与只落后 1 个版本，中英各一次。
- 在本地用替身 `gh` 运行 `publish` 任务新增的步骤：草稿与预发布被排除，只取 4 个旧版，安装说明与 `\r` 去掉，
  原有的 `notes` 与 `platforms` 不变。
- v0.16.0 发版后核对线上 `latest.json`：`history` 依次为 0.16.0、0.15.1、0.15.0、0.14.0、0.13.2，安装说明已去掉，
  `platforms` 7 个条目齐全。弹窗的新样子要等下一个版本发布后，在装着 v0.16.0 的应用上才能在真机看到。

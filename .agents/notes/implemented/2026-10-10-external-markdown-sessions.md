# Agent Note: 外部会话——临时导入他人导出的 Markdown

Status: implemented

## Problem

别人用本应用导出单会话 Markdown 发给用户，通常一份含思考与工具调用的详细版、一份只含对话的简洁版。
用户想借本应用的对话详情阅读，但不想把它们变成本机会话：不能写入 `~/.claude` / `~/.codex`，也不该
混进自己的项目、统计与搜索。需要决定导入物的生命周期、两个版本的关系、呈现位置和支持的格式。

## Proposal

- 默认临时：导入的会话只在内存里，应用退出即消失；用户点「保留」才把原始 Markdown 复制到应用数据目录，
  临时和已保留的都能「删除」。理由：用户要的是临时导入、自行选择删除或保留，保留也只留在本应用内。
- 同一会话（产品 + 会话 ID）的详细版与简洁版合并为一条，详情页在「完整 / 只看对话」之间切换；只导入了
  简洁版时只能看对话。理由：用户确认合并为一条、可切换。
- 侧栏独立入口「外部会话」，打开后复用现有对话详情的呈现；外部会话不进入项目列表、概览统计、Prompt
  搜索、全文搜索与 Token 汇总。理由：用户确认独立入口、不进统计，避免与自己的数据混在一起。
- 只支持单会话导出（「# 对话导出」/「# Conversation Export」，中英文标签）；合并批量导出、index.md、
  Prompt 与搜索结果导出拒绝并说明原因。理由：用户只选了单会话导出。

## Decision

已按 Proposal 落实。实现中的取舍：

- 解析是 `export.rs` 单会话导出的逆过程，只认完整的消息标题格式，用户正文里的 `##` 标题不会误切。
  单会话导出格式因此成为解析契约，改动导出格式要同步解析与测试。
- 「只看对话」优先显示简洁版文件，没有时由详细版按导出不含执行过程的规则过滤；两份来自同一次导出时
  结果逐条一致。
- 不套用本机会话 24,000 字符的展示截断：Markdown 是唯一来源，工具块默认折叠。
- 导出没有逐次调用用量：详情不显示 Token 用量明细面板，只显示文件头的 Token 总量与估算成本；不提供
  再次导出与 Resume 命令。
- 时间按文件里的分钟级时间、以本机时区解析后原样显示。
- 外部会话里 Markdown 的远程图片不加载，只显示为链接，点击才交给系统浏览器（用户确认）。理由：文件来自
  他人，自动加载会让对方借图片请求得知文件被打开。本机会话的图片行为不变。

id、槽位、围栏判定与保留目录的规则以开发文档 §12 为准。

## Consequences

- 同一条消息里的多个文本块合并为一段；导出时已显示为助手的 system 消息无法还原。
- 没有思考与工具调用的会话，详细版与简洁版无法区分，都按简洁版处理（内容相同）。
- 工具结果正文本身就是一份导出（含标记行与 ```` 围栏）时，块边界可能误判。

## Verification

- `external.rs` 单元测试：合成会话经 `export.rs` 渲染（中英文、含 / 不含执行过程）再解析的往返一致；
  详细版过滤与简洁版逐条一致；拒绝其他导出与任意 Markdown；CRLF、BOM、单独 CR、空思考块；存储的合并、
  替换、保留后重新载入、覆盖读不回来的目录、删除与非法 id。
- 一对真实 Codex 导出（877 / 130 条消息）经 opt-in 冒烟只读核对，过滤结果与简洁版 0 处不一致；未入库。
- 前端在浏览器中用模拟 IPC 渲染列表与详情（浅色 / 深色、中英文），确认了视图切换时的查找状态、双击删除
  与重复点击视图三处修正；外部会话中各种写法的远程图片都显示为链接且不发请求，本机会话照常加载。
  未在 Tauri 窗口内验收。
